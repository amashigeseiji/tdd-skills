# 装置主語 root の例外を削除する

**日付:** 2026-08-14
**発端:** tdd-refactor 診断スキル化の実装（redesign/tdd-refactor-diagnosis/03）の途中。
feedback の登記の一項「装置主語 root のフェーズは登記するものを持たない」が再節合型プランを被覆しないことを確認していて、そもそも装置主語 root のフェーズが現状の体系で成立するのか、という疑問が出た。

## 判断

decompose の装置主語 root の例外を削除する。
root は役割主語のユースケースのみになる。

## 理由

- 例外の使い道として定められていたのは「配線済み装置の能力改善（共有中間ノードの取り出し）」だけであり、これは挙動を保存する作業である。
  いまは診断（/tdd-refactor）→ 再節合（/tdd-run refactor）の軌道が同じ操作を、台帳による回帰面の確定と挙動保存の敷設つきで担う。
  基盤節（共通因数のくくり出し、影響先の列挙）が共有中間ノードの取り出しの後継である。
- ルーティングが入口文書のジャンル判定になったことで、正規の入口も消えた。
  decompose に入るには problem.md が要るが、挙動が変わらない構造の話は problem.md が様式上受け取れない（診断スキル化の出発点の問題認識）。
- 例外は再節合工程（2026-08-06）より前に作られたもので、当時は挙動を変えない構造改善の唯一の受け皿だった。
  役目を終えた残置物である。

## 変更箇所

- `tdd-run/subcmds/decompose.md` — 例外の枝の削除、手順3（root を赤で置く）の読み分けの解消、root の承認・出口ゲートの限定句の削除
- `tdd-run/subcmds/compose.md` — 手順3（root が緑になったことを確認する）の読み分けの解消、材料化の登録済み概念の列挙から除去
- `tdd-feedback/skill.md` — 登記の一項「装置主語 root のフェーズは登記するものを持たない」の削除（後継は「再節合型プランの周回では新規の登記は原則発生しない」の一項）
- `tdd-run/norms/tree.md` — 「root は原則として役割主語」の「原則として」（例外の含み）の削除、層の整合則の限定句の解消

## 残すもの・再導入の条件

- `docs/references/2026-08-07-act-ledger.md` の「装置主語 root のフェーズは昇格するものを持たない」は当時の構想の沈殿としてそのまま残す。
- 役割に帰属できない正当な装置主語 root の事例が実際に現れたら、その時に意図的に再導入する。

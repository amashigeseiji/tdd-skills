# /tdd-update acts — 行為の登記簿への遡及登記

## 目的

台帳（`docs/acts.json`）導入以前から tdd-skills で開発してきたレポジトリに、
すでに使用で清算されている行為を遡って登記する。
レポジトリごとに実質一度きりの移行だが、**一括の機械処理ではない** —
源泉の事情はレポジトリごとに異なるため、状況を読みながら対話（表＋承認）で進める。

先に必ず Read する:

| ファイル | 内容 |
|---------|------|
| `${CLAUDE_SKILL_DIR}/../tdd-feedback/acts-format.json` | 台帳の意味とエントリのフォーマット（登記判定の規則を含む） |
| `${CLAUDE_SKILL_DIR}/../tdd-run/norms/dialogue.md` | 対話規範 — 提示 → 承認の作法 |
| `${CLAUDE_SKILL_DIR}/../tdd-run/norms/vocabulary.md` | 語彙規範 — 語彙登録ルール（actor の登録に使う） |

台帳の読み書きはツール経由で行い、`acts.json` を Edit/Write や python 等で直接操作しない。

## 適用条件

対象は **tdd-skills を使って開発してきたが、台帳導入以前だったレポジトリ**。
源泉が存在することを前提とする:

- 生きている `tests/acceptance/` — witness の実体
- `plans/archives/<project>/user-story.md` — claim の文言の材料
- `plans/archives/<project>/findings.md` の利用仮説照合 — 清算の証拠と日付

源泉が一つも無いレポジトリ（tdd-skills をこれから導入する）は適用外 —
末尾の「源泉が無いレポジトリ（ゼロベース導入）」の節に従う。

## 原則

1. **源泉はツリーではない。** 成層以前のフェーズのツリー（test-tree.md）に行為層は存在しない。
   アーカイブの test-tree.md は `settled.devices` / `settled.unitTests` の best-effort 補完の参考に留める。
2. **現在有効な形だけを登記する。** 再定義を経た行為は最終形のみ。
   supersede の連鎖を遡って再構築しない（歴史はアーカイブが持つ）。
3. **witness がある行為に限定する。** 手動確認のみで清算された行為は登記せず、保留として記録する（手順6）。
4. **一括機械処理はしない。** actor ごとに表を提示し、承認を得てから一件ずつ書く。

## 手順

**1. 現状の確認**

`<meta>` は skill.md の手順で確定済みとする。既存の登記を確認する:

```bash
node "$(realpath "${CLAUDE_SKILL_DIR}")/../bin/acts-search.js" -a -s
```

すでに登記があるレポジトリでも手続き自体は妨げない（防衛線が重複を止める）が、
どの範囲が未登記かをここで把握しておく。

**2. 生きている受け入れテストから歩く**

`tests/acceptance/`（相当のディレクトリ）のシナリオ（describe）を列挙し、
シナリオ → 行為の対応づけを作る。テストを実行し、**現在緑であること**を確認する。
赤のシナリオは登記候補から外し、完了報告に理由つきで載せる。

**3. 行為の書き起こし**

過去のツリーには行為層の記述が無いため、アーカイブの user-story.md・findings.md の
利用仮説・受け入れテストの記述から actor と行為を拾い、claim を書き起こす。
形は acts-format.json に従う（actor は別フィールド、claim は述語のみ）。
文言はここでは案であり、登記の承認で確定する。

**4. 登記判定**

アーカイブの findings は仮説単位の照合しか持たない（仮説は行為の集合より広い）ため、
行為単位では次の解釈規則で判定する:

- 当時の操作の事実（findings の事実の節）にその行為が現れている
- findings でその行為に失敗・違和感が帰属されていない
- witness（受け入れテスト）が現在緑である

三つすべてを満たす行為だけを登記候補にする。**外れたまま終わったシナリオは登記しない。**

**5. actor の辞書確認と登記（表＋承認）**

登記候補の actor が `docs/dictionary.json` に `domain: actor` で無ければ、
**先に語彙登録ルール（語彙規範 — 表＋承認）で登録する**。
user-story のロール名と辞書名の表記が揺れる場合は、登記の承認で辞書名へ正規化する。

actor ごとに表を提示し、承認を得る:

| claim（案） | witness | settled |
|------------|---------|---------|
| <述語> | <テストファイルパス>#<describe表題> | date / project / devices / unitTests |

- `settled.retro: true`。`settled.date` は元の findings の日時、`settled.project` はアーカイブのプラン名
- `settled.devices` / `settled.unitTests` は best-effort — 生きているテストファイル・アーカイブと
  突き合わせて実在確認できたものだけ書き、推測で写経しない
- `parent` は原則書かない（遡及エントリはフラット — 成層以前のツリーに行為層の記述が無いため）

承認を得たエントリを一件ずつ書く:

```bash
node "$(realpath "${CLAUDE_SKILL_DIR}")/../bin/acts-write.js" add <<'EOF'
{ "actor": "<辞書の actor 名>", "claim": "<述語>", "context": "<辞書の context.dir>",
  "witness": { "acceptance": ["<テストファイルパス>#<describe表題>"] },
  "settled": { "date": "<YYYY-MM-DD>", "project": "<プラン名>", "retro": true } }
EOF
```

**防衛線の停止が出たら、上書きせずユーザーに諮る。**
別の行為だと確認できた場合のみ `--allow-similar` で越える（同一 claim は越えられない）。

**6. 保留の記録**

witness の無い行為（手動確認のみで清算）は登記せず、`<meta>/docs/acts-pending.md` に記録する:

```markdown
# 行為の登記保留

witness（受け入れテスト）が無いため登記しなかった行為。
受け入れテストが書かれたときに、通常の登記（feedback の毎周登記）へ回す。

| actor | claim | 源泉 | 保留理由 |
|-------|-------|------|---------|
```

**7. 検証と完了報告**

```bash
node "$(realpath "${CLAUDE_SKILL_DIR}")/../bin/acts-write.js" check
```

報告する内容:

- 登記した行為（actor 別）
- 保留にした行為（手動確認のみ）
- 登記しなかったシナリオと理由
- スキーマ・ツールで困った点があれば列挙する — スキルリポジトリへの改善入力として持ち帰る

## 源泉が無いレポジトリ（ゼロベース導入）

tdd-skills を初めて導入するレポジトリでは、上の源泉が一つも存在しない。
このとき**一括の先行登記はしない**。現状挙動には約束と偶然（bug-for-bug な挙動）が
混ざっており、機械的に全部を載せると台帳が「清算済み主張の登記簿」から
「現状挙動の棚卸し」に変質し、refactor の固定点が偶然まで固定してしまう。

- 導入時は空の台帳から始める。台帳ファイルは初回書き込み時に作られる（tdd-init は台帳を作らない）。
- 充填はオンデマンドで行う: 新規開発分は feedback の毎周登記で前向きに載る。
  既存挙動は、refactor が触った範囲の回収・特性テストの敷設（フォールバック経路）から
  「未登記挙動」として findings に上がったものを、本手続きの登記判定（手順4〜5）で登記する。
- 特定の重要領域を意図して先行登記したい場合は、別途セッションを立てる。
  その場合の源泉は本手続きと異なる: 生きているコードと UI からの回収（refactor 手順2の姿勢）＋
  人間が持つ実使用の知識。witness は発見ではなく**書き起こし**になる（受け入れ粒度の特性テスト）。
  settled は `retro: true` + `evidence: "in-use"`、date は登記日
  （成立した歴史的日付は不明であり、偽の精度で過去日付を書かない）。
  登記するかどうかは行為ごとに人間の承認で決める — **約束と偶然の選別は機械化しない**。
